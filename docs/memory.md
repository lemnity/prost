## Решения

- **2026-10-29 — Поля группировки Oasis записываются наоборот.** У Oasis `group_id` — модель, `color_group_id` — цвет (размеры внутри); у нас (как у gifts.ru) наоборот. Раньше писали как есть, и каждый цвет Oasis был отдельной карточкой (23 620 карточек вместо 8 741 модели). `saveOasisPage` меняет поля местами; данные в базе исправлены разовым обменом 29.10 (страница товара и выдача проверены). Партии Oasis с артикулом на «p» (распродажа остатков, своя цена) Oasis ведёт отдельными моделями — так и показываем, иначе в одной карточке один цвет с двумя ценами.
- **2026-10-29 — Цвета модели в витрине** (`src/components/catalog/product-colors.tsx`, `withSwatches` в `src/server/catalog.ts`). После выдачи одним запросом по `color_group_id` собираются цвета (группа = `group_id`, остаток — сумма по размерам), в карточку — `Product.swatches`, если цветов больше одного. Клик выбирает цвет прямо в карточке, а не уводит на страницу. Работает для обоих складов (см. запись ниже про поля Oasis).
- **2026-10-28 — Поиск в шапке: товары или Виктория** (`src/components/layout/ai-search.tsx`, `/api/search/suggest`). Раньше Enter всегда открывал чат. Теперь при наборе от 2 символов — подсказки (до 5 товаров через `listProducts` с кэшем, до 3 разделов из снимка дерева, точный артикул первым), Enter ведёт на `/search`. Виктория — строкой в подсказках и кнопкой «AI». Если запрос похож на вопрос («?», «что подарить», «до 2000 ₽», 5+ слов), её строка первой и выбрана сразу, Enter открывает чат. Недавние запросы — в `localStorage` (`ps_search_recent`).
- **2026-10-16 — Доставка отслеживается вручную** (`src/lib/shipping.ts`, колонка `orders.shipping` JSON): менеджер ставит этап, перевозчика и трек-номер. Ссылка «Отследить» есть только у СДЭК и Почты России (адрес их страниц отслеживания известен), у остальных клиент ищет по номеру на сайте ТК. Письмо клиенту — один раз, при переходе в «Отправлен». Автоматический статус из API ТК — когда появятся договор и ключи.
- **2026-10-16 — Виктория не обещает «вернусь с ответом»** (сама написать первой не может): уточнит менеджер в рабочее время. Когда клиенту ждать расчёта или макета, один раз предлагает оставить номер для обратного звонка или позвонить самому. Сообщение чата с номером телефона приходит менеджеру с темой «Перезвонить клиенту: заявка …». Обращение в чате — по имени из профиля (`greetName`), а не первым словом поля «Имя» (там «Фамилия Имя Отчество»).
- **2026-10-16 — «Наши бренды» вместо «Нам доверяют»** на главной. Логотипы — с prostyle.gifts (`/api/cms/directoryFiles?directoryPath=/content/gifts-theme/brands&photolabId=7190`), обрезаны по краям и сохранены в WebP высотой 120 (`public/images/brands/`). В сетке выравниваются по площади, а не по высоте (`src/components/home/brands.tsx`). Ссылок на поиск нет: по 10 из 17 брендов поиск по названию пуст.
- **2026-10-16 — Цены без «от»:** у товаров, в корзине, заявках, письмах и меню пишем просто «N ₽». «От» оставлен у порогов и диапазонов (фильтр цены, минимальный заказ, тиражи прайса нанесения).
- **2026-10-13 — Цены нанесения — из прайса владельца, единый источник `src/lib/print-prices.ts`.** Из него строятся таблицы вкладки «Прайс-лист» (`priceSections`, подставляет `getApplicationType`) и калькулятор кнопки «Рассчитать нанесение» (`calcPrice`, окно `print-calc.tsx`). Расчёт ориентировочный, заявка уходит в «Обращения» с типом `calc`. Тот же расчёт — в окне «Добавить нанесение» на карточке товара (`EstimateFields`), сумма сохраняется в `branding.estimate` и попадает в заявку и письма. Виктория получает выжимку прайса (`priceDigest` в `KNOWLEDGE`) и называет стоимость нанесения только как ориентир. Где прайса нет, кнопка ведёт на обратный звонок, а на вкладке — текст из `application-types.json` («рассчитает менеджер»). Заголовки колонок держать короткими: на телефоне длинные налезают. Новый вид = запись в `application-types.json` + карточка в `applications` (`src/content/home.ts`) + `public/images/application-types/<slug>/banner.webp` и `public/images/applications/<slug>.webp`.
- **2026-10-13 — Баннеры и новости — в базе, правятся в админке** (раздел «Сайт»). Файлы `src/content/home.ts` (`banners`) и `news.json` — начальное наполнение и запасной вариант без базы. Удаление мягкое: удалённое не возвращается при следующем наполнении. Картинки из админки лежат в `UPLOAD_DIR` (таблица `files`, `order_number = 'site'`) и отдаются публично по `/media/<id>`. Главная, `/news`, `/news/<slug>` и `/sitemap` собираются при запросе с кэшем в памяти; `pages.xml` карты сайта обновляется раз в 6 часов.
- **2026-10-13 — Нанесение на карточке товара — как на старом сайте** (prostyle.gifts, кнопка «Добавить нанесение»): способ из характеристик товара (Oasis — «Метод нанесения», gifts.ru — «Виды нанесения»), комментарий, логотип. Стоимость нанесения не считаем — только менеджер. Логотип грузится сразу (`/api/uploads`, в `files` с `order_number = 'draft'`), к заявке привязывается при оформлении; черновики старше 7 дней удаляются.
- **2026-10-12 — Главная и `/sale` собираются при запросе** (`force-dynamic`). ISR-заготовка со сборки (без базы) после перезапуска показывала старый запасной список распродажи.
- **2026-10-12 — Распродажа недели — со склада:** скидка от 20%, остаток от 20 шт., одна карточка на модель. Порядок задаёт CRC32 от ключа недели, поэтому подборка меняется ровно при сбросе таймера.
- **2026-10-12 — Большие загрузки — по очереди** (`heavy()`), повтор блокировок MySQL в `exec`. Причина — deadlock при одновременных каталогах Oasis и gifts.ru.
- **2026-10-12 — Ручной запуск синхронизаций из админки — в фоне** (`after()`): nginx обрывает запросы через 60 с.
- **2026-10-10 — Виктория:** честность важнее «живости». На прямой вопрос о том, человек ли она, признаёт, что виртуальный помощник. В письме «Ваш заказ» она и так названа виртуальным менеджером.
- **2026-10-10 — Ответ окна поиска — JSON** `{text, picks, more_text, more, question}`. Сервер раскладывает его на отдельные сообщения с карточками. Тире вычищаются (`noDash`).
- **2026-10-10 — Карта сайта — свои маршруты**, а не `generateSitemaps`: части считаются из базы при запросе, а при сборке базы нет.
- **2026-10-10 — Одна страница товара на модель** в карте и выдаче. Цвета и размеры — варианты на карточке.
- **2026-10-10 — Тяжёлые поля вынесены в `oc_product_details`:** таблица выдачи сжалась с 400 до 30 МБ.
- **2026-10-10 — Количества в разделах — модели** (`COUNT(DISTINCT COALESCE(color_group_id, id))`), а не строки размеров.
- **2026-10-10 — gifts.ru:**
  - фото берутся с публичного `files.gifts.ru/reviewer/`, хостить у себя не нужно;
  - выгрузка по разделам невозможна, обновляется только целиком.
- **2026-10-10 — Единое дерево разделов — Oasis.** Разделы других складов сопоставляются через `category_map` (умолчания — `src/server/gifts-map.ts`). Так один товар не попадает в разные разделы в зависимости от склада.

## Инциденты и уроки

- **2026-10-17 — Взлом гипервизора FirstVDS.** С 12:27 до 22:34 МСК через уязвимость в их системе виртуализации могли читать файлы с диска сервера. Следов входа на сам сервер нет: 18.10 проверены журналы SSH (с 17.10 входы только по ключу деплоя, неудачные попытки на обычном фоне), nginx (входов на сайт после 17.10 нет; входы с адресов владельца), панели, а также `authorized_keys`, пользователи, cron, systemd, SUID, пользователи MySQL — чужого нет. Считаем утёкшим всё на диске: `.env`, `/root/.my.cnf`, ключи DKIM и TLS, `shadow`, базу и бэкапы. Реальных клиентов в базе не было (только админ, демо и тестовые заявки владельца), поэтому Роскомнадзор не уведомляли. Сделано: отключён `qemu-guest-agent` (канал, которым гипервизор читает файлы и запускает команды в ВМ; заодно в панели FirstVDS не работает сброс пароля), панель ISPmanager закрыта снаружи, FTP выключен, SSH только по ключу (`/etc/ssh/sshd_config.d/00-prostyle.conf`), бэкапы шифруются age. Шифрование диска (LUKS) не делали: ключ всё равно в памяти, а перезагрузка требует ручного ввода. Урок: от гипервизора ВМ не защитить, поэтому держать на сервере минимум секретов и ничего лишнего в открытом виде.

- **2026-10-14 — Виктория показала клиенту сырой JSON.** После добавления прайса нанесения ответы стали длиннее и обрывались на `max_tokens` 600, разбор падал, а запасной путь выводил текст как есть. Решение: лимит окна поиска 1200, чата 1000; `salvage()` в `src/server/ai.ts` достаёт дописанные поля из оборванного JSON. Урок: при росте `KNOWLEDGE` проверять длину ответов.
- **2026-10-13 — «Фото скоро появится» на товарах gifts.ru.** Их сервер `files.gifts.ru` стал обрывать загрузку картинок, которые браузер помечает как запрос с чужого сайта (`Sec-Fetch-Site: cross-site`); curl без этих заголовков получает фото нормально. Решение: nginx отдаёт фото через `/gifts-img/` (прокси на `files.gifts.ru/reviewer/` без `Sec-Fetch-*` и `Referer`, кэш `/var/cache/nginx/gifts`, до 2 ГБ, 30 дней), в базе и синхронизации адреса фото gifts.ru — `/gifts-img/...`; для dev — `rewrites` в `next.config.ts`.
- **2026-10-12 — Диск 100%.**
  - Причины:
    - кэш страниц Next.js писал на диск каждую открытую роботом страницу товара (`.next-prod/server/route-cache`, 5,7 ГБ, 82 тыс. файлов);
    - двоичные журналы MySQL — 3 ГБ.
  - Последствия: MySQL «No space left on device», синхронизации падали, страницы не обновлялись.
  - Решение:
    - `experimental.isrFlushToDisk: false`;
    - `disable_log_bin` (копия настроек — `mysqld.cnf.bak`);
    - ежечасная страховка `/etc/cron.hourly/prostyle-disk-guard`.
  - Урок: при «что-то не обновляется» сначала `df -h /`.
- **2026-10-12 — Сборка падала, хотя код ни при чём:**
  - нет доступа к `fonts.gstatic.com` (`next/font` качает шрифты при сборке);
  - испорченный `.next/dev/types/routes.d.ts` от dev-сервера — удалить и перезапустить dev.
- **2026-10-10 — Браузер держал старое меню каталога** (`/catalog-menu.json` без запрета кэша). Решение — `?v=<версия дерева>`.
- **2026-10-10 — Синхронизация Oasis помечала товары gifts.ru удалёнными.** Решение — все UPDATE и DELETE синхронизаций фильтруются по `supplier`.
- **2026-10-10 — Выдача 6–27 с:** таблица не помещалась в буфер MySQL (128 МБ). После `DROP COLUMN` в MySQL 8 файл не уменьшается — нужен `ALTER TABLE … FORCE`.
- **2026-10-09 — Полная синхронизация помечала всё удалённым:** `DATETIME` без миллисекунд. Метку начала нужно округлять до секунды.
- **2026-10-09 — Смешение кодировок** `utf8mb4_0900_ai_ci` / `utf8mb4_unicode_ci`. Всё переведено на `utf8mb4_unicode_ci`, явно в схеме и пуле.
- **2026-10-09 — mail.ru отклонял письма как спам:** помогли SPF, DKIM, DMARC (reg.ru) и PTR `82.146.52.154 → prostyle.agency` (FirstVDS).
- **2026-10-09 — Номера заявок совпадали после удаления:** номер считается от максимального за день, а не от количества.

## Локальная разработка

- **Запуск:** `npm run dev -- --port 3000` с переменными из локального `db.env` (не в репозитории). База — через туннель `ssh -i ~/.ssh/prostyle_deploy -f -N -L 3307:127.0.0.1:3306 root@82.146.52.154`.
- **Туннель** падает после перезапуска MySQL на сервере — поднимать заново.
- **Скриншоты и проверки** в браузере — Playwright (headless shell из `~/Library/Caches/ms-playwright`). Файлы складывать вне репозитория.
